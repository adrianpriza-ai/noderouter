what the router does for you

Local OpenAI endpoint

One port serves /v1/chat/completions, /v1/responses, /v1/embeddings and the rest, so existing clients and SDKs keep working unchanged.

Model-based routing

The model in the body picks the provider, including renamed, namespaced and round-robin ids across a unified model group.

Endpoint pools

Give a provider several upstream base URLs and spread the load by rotate, primary, first or random.

Endpoint health

Failed endpoints are benched, and a background probe returns them to the pool once they answer again.

Rotating proxy pool

Requests rotate through tested free proxies and retry across both proxies and backends when a hop dies.

Chat ↔ Responses

A provider that speaks only one surface still meets the other: the router rewrites the request, the path and the answer, streaming included.

Every request, one path.

no dependencies outside the standard library
client noderouter:32256 proxy pool provider /v1

The router reads the model from the body, rewrites the id, injects the provider key, and refreshes the proxy list on a cron schedule (midnight by default).

Point a client at it.

from source, four commands 
$ go build -o noderouter .
$ ./noderouter init      # write ~/.noderouter/models.json
$ ./noderouter convert   # fetch + test proxies -> ~/.noderouter/ports.txt
$ ./noderouter           # serve on 127.0.0.1:32256

$ export OPENAI_BASE_URL=http://127.0.0.1:32256/v1
$ export OPENAI_API_KEY=whatever   # the router swaps in the real key

Whatever your provider exposes works — chat, responses, embeddings, images, audio. Streaming passes through chunk by chunk, and every answer carries X-Noderouter-Proxy so you can see which hop served it.
